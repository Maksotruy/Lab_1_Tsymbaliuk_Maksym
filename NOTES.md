# Робочі нотатки

Для `HomeScore` та `AwayScore` обрано тип `int`, оскільки кількість голів є цілим невід'ємним числом.

Для `MatchDate` обрано `DateOnly`, оскільки для обліку матчу потрібна саме дата проведення без часу.

Для `Stadium` використано `string?`, оскільки інформація про стадіон може бути відсутньою.

Для `Status` використано `enum MatchStatus`, оскільки статус матчу має обмежений набір можливих значень: запланований, завершений або скасований.
## Entity Framework Core та SQLite

Для роботи з базою даних використано Entity Framework Core та SQLite.

Створено контекст `FootballMatchesContext`, який містить `DbSet<FootballMatch> FootballMatches`.

Для підключення SQLite використано базу даних `footballmatches.db`.

Створено першу міграцію `Init` та застосовано її до бази даних за допомогою команд `dotnet ef migrations add Init` і `dotnet ef database update`.

У поточній моделі немає властивостей типу `decimal`, тому додаткове перетворення типів для SQLite не потрібне. Таке перетворення могло б знадобитися, якби модель містила десяткові значення типу `decimal`, наприклад ціну або іншу грошову величину.

## Лабораторна робота №4. Генератор сторінок для роботи із записами

### 1. Директива @page

`OnValidSubmit` викликає метод збереження після успішної перевірки форми. `NavigateTo` забезпечує повернення користувача до списку футбольних матчів після створення або редагування запису.

# Лабораторна робота №13

## Тема
Конфігурація, логування, публікація та контейнеризація вебзастосунку FootballMatches.

## Мета роботи
Навчитися налаштовувати конфігурацію ASP.NET Core, використовувати журналювання подій, автоматизувати застосування міграцій бази даних, перевіряти роботу застосунку в середовищі Production та виконувати публікацію готового програмного продукту.

## Хід виконання роботи

### 1. Налаштування конфігурації

У файлі `appsettings.json` налаштовано рядок підключення до бази даних SQLite та параметри застосунку.

Використано такі налаштування:

- `ConnectionStrings:Default` — підключення до SQLite.
- `FootballMatches:PageSize` — кількість записів на сторінці (12).
- `FootballMatches:Title` — назва застосунку FootballMatches.

### 2. Налаштування логування

Для журналювання подій передбачено використання `ILogger<T>`.

Логування дозволяє відстежувати операції створення, перегляду, редагування та видалення записів, а також повідомлення про помилки.

Рівні журналювання налаштовано через `appsettings.json`.

### 3. Автоматичне застосування міграцій

У файлі `Program.cs` налаштовано автоматичне застосування міграцій Entity Framework Core під час запуску застосунку.

Під час перевірки отримано повідомлення:

`No migrations were applied. The database is already up to date.`

Це підтверджує, що структура бази даних відповідає наявним міграціям.

### 4. Перевірка середовища Production

Застосунок запущено в середовищі Production за допомогою команди:

`dotnet run -c Release --no-launch-profile`

У терміналі отримано повідомлення про успішний запуск:

`Application started.`

`Hosting environment: production`

`Now listening on: http://localhost:5000`

У конфігурації передбачено обробку помилок через `UseExceptionHandler`.

### 5. Публікація застосунку

Виконано публікацію FootballMatches у конфігурації Release командою:

`dotnet publish -c Release -o ../publish`

Опубліковані файли розміщено в окремій папці `publish`.

Для запуску використано команду:

`dotnet FootballMatches.dll`

Під час перевірки встановлено, що основний проєкт та опублікована версія можуть використовувати різні файли SQLite через відносний шлях підключення.

Для доступу до основних даних у конфігурації опублікованої версії зазначено шлях до бази даних головного проєкту.

### 6. Перевірка Docker

Для перевірки наявності Docker виконано команду:

`docker --version`

Отримано повідомлення:

`docker : The term 'docker' is not recognized`

Таким чином, Docker CLI у локальному середовищі недоступний. Збирання та запуск Docker-контейнера не виконувалися.

### 7. Оновлення документації

Доповнено файл `README.md` інформацією про конфігурацію, базу даних, логування, середовище Production, публікацію Release та Docker.

## Результат роботи

Налаштовано конфігурацію FootballMatches, перевірено автоматичне застосування міграцій Entity Framework Core та успішний запуск застосунку в середовищі Production. Виконано публікацію Release, перевірено розташування баз даних SQLite та оновлено документацію проєкту.

Під час збирання також виявлено попередження NuGet щодо вразливостей залежностей, які потребують подальшого оновлення.

Отримано практичні навички роботи з файлом `appsettings.json`, міграціями Entity Framework Core та середовищем Production. Виконано публікацію FootballMatches у конфігурації Release.
